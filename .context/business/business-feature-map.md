#### Feature: Personal Access Token (PAT) Management

| Aspect | Value |
|---|---|
| **ID** | FEAT-005 |
| **Status** | ⚠️ Partial — **SECURITY BUG OPEN** |
| **Endpoints** | `POST /api/v1/tokens`, `GET /api/v1/tokens`, `DELETE /api/v1/tokens/{id}` |
| **UI** | None (API-only — PAT management UI is BK-88, Ready For Dev) |
| **Users** | Authenticated (Cookie required for creation; Bearer for API calls) |
| **Dependencies** | `access_tokens`, `access_token_secrets` |
| **Evidence** | `app/api/v1/tokens/route.ts`, `app/api/v1/tokens/[id]/route.ts` |
| **Jira** | BK-88 (Ready For Dev), BK-134/BK-135 (Open bugs) |

**Capabilities:**
- [x] Issue PAT with configurable scopes: `atc:read`, `atc:write`, `run:execute`, `workspace:admin`
- [x] List caller's tokens (no secret — prefix only, wrapped in `{tokens:[...]}`)
- [x] Soft-revoke token by ID (sets `revoked_at`, never hard-deletes)
- [x] Token family prefix `bk_pat_` for secret-scanner detection
- [x] Optional workspace binding and expiry (max 365 days)
- [x] SHA-256 hash stored in sibling table (`access_token_secrets`)
- [x] PATs cannot create PATs (chicken-and-egg protection — 403 with `forbidden` code)
- [ ] **Role gate for `workspace:admin` scope** — **BK-134/BK-135 OPEN** — member-role users can self-issue `workspace:admin` tokens; no 403 enforcement
- [ ] PAT management UI page (BK-88 — Ready For Dev)

> **Security Gap**: `POST /api/v1/tokens` does not verify the caller holds `admin` or `owner` role before minting `workspace:admin` PATs. 136 active `workspace:admin` PATs on staging — some from member-role users. `workspace_id = NULL` on affected tokens means global admin access across all workspaces.
